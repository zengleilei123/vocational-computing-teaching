# 对自己的地图作品集运行 A01—A12

本运行器对**你明确指定的本机网页**执行地图作品集自动检查，使用 Python `unittest` 与 Playwright。它不启动服务器，不自动选择教师实现；学生仍需完成 [CAPSTONE](../../curriculum/ai-assisted-development/CAPSTONE.md) 的 V1/V2 功能。

先按[学生启动卡](../../classroom/robot_portfolio/student/START.md)运行自己的工程，再按本页配置界面适配。普通表单、原生 `<select>` 存档列表、DOM 对话框或原生 `window.confirm` 属于当前支持范围，并须保留原地图格子的行列／地形无障碍标签语义。卡片列表、IndexedDB、云端存储或自行重写的整个机器人界面需要扩展适配；不能仅因现有适配不支持就判定作品业务错误。

自动检查不返回分数。完成三个独立反例、个人讲解、故障修复和回归的要求仍以任务书及[提交记录](../../classroom/robot_portfolio/student/SUBMISSION.md)为准。工具的技术依据见 [SOURCES](SOURCES.md)。

## 1. 准备环境与自己的服务

基础网页运行仍只需 Python 3.10+ 与普通浏览器；下面是可选的自动浏览器检查依赖。建议在作品根目录建立虚拟环境。先用已确认可用的 Python 创建环境，后续安装与验收始终使用该环境中的解释器，避免把依赖装进另一个 Python。

Windows PowerShell（创建环境时，`python` 可换成 `py -3`）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install "playwright==1.57.0"
.\.venv\Scripts\python.exe -m playwright install chromium
```

macOS/Linux（创建环境时，`python3` 可换成已确认的 `python`）：

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install "playwright==1.57.0"
./.venv/bin/python -m playwright install chromium
```

这些命令直接调用虚拟环境的解释器，无需激活脚本。下文验收命令中的 `python` 相应换成 `.\.venv\Scripts\python.exe` 或 `./.venv/bin/python`。如果提示 `externally-managed-environment`，先核对是否误用了系统 Python；本流程不需要覆盖系统包管理保护。环境隔离依据见 [S7](SOURCES.md)。

已有兼容 Chromium 时可设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指向其可执行文件。运行器不会自动下载浏览器、安装依赖或修改浏览器配置；缺依赖应记录原始错误。首次安装需要联网，之后自动操作针对本机服务。

在**自己的作品根目录**启动学生工程，保留这个终端：

```bash
python -m projects.robot_playground.server --port 8765
```

打开 `http://127.0.0.1:8765`，确认它展示自己的改动。若使用其他端口，同时修改服务命令和后续 `--url`。URL 必须是带明确端口的回环 HTTP 地址；不要填写公开站点、同学机器或教师参考服务。

## 2. 复制并填写适配模板

在 `classroom/robot_portfolio/student/` 中将 [acceptance-adapter.example.json](../../classroom/robot_portfolio/student/acceptance-adapter.example.json) 复制为 `my-acceptance.json`。保留原模板，再按当前工程填写副本。

**模板故意不能直接运行。** 已有机器人控件按学生起点填写，新增作品集控件、作品标签和存储键保留 `TODO`。这会产生配置阻塞，避免把一个尚未指定对象的模板误报为通过。它不包含保存或导入的实现代码；填写选择器也不会让缺失的功能自动出现。

### 需要说明的配置

| 字段 | 填写内容与含义 |
|---|---|
| `schema_version` | 固定为整数 `1`，表示适配配置版本；与地图文件的 `version` 是不同契约 |
| `target_kind` | 学生作品使用 `student`；`reference` 仅供教师校准，需额外命令行开关 |
| `label` | 自己的作品代号；不填真实姓名学号，不保留占位文字 |
| `source_files` | 明确列出 HTTP 资产路径 `url` 及相对于 `--source-root` 的本地文件 `path`；包含自己新增并实际加载的脚本 |
| `storage_keys` | 作品集实际使用的一个或多个 `localStorage` 键；不要随意填写教师键或遗漏自己新增的存档键 |
| `duplicate_policy` | `confirm`：同名时可确认覆盖；`reject`：拒绝同名并提示改名。两种方式均不得静默覆盖 |
| `confirmation` | `dom`：页面内对话框；`native`：原生 `window.confirm`。按实际实现选择 |
| `selectors` | 把下列语义名称映射到实际控件；不是让你把控件改名为模板中的字符串 |
| `archive_placeholder_values` | 可选，默认 `[""]`；原生选择列表中不代表地图的占位选项 `value`，不能包含真实地图项 |
| `timeout_ms` | 可选，默认 `5000`，范围 `1000`–`30000`；等待页面反馈，不通过无限等待掩盖缺失功能 |

`source_files` 示例沿用学生起点的 `/`、`/app.js`、`/style.css`。若把存档逻辑拆到新脚本，应增加该脚本的真实 URL 和本地相对路径。服务生成的页面若与列出的本地 HTML 字节不同，会阻塞资产核对；应解释生成流程并扩展验证方式，不能把不匹配当作已经核实。

每个定位符采用以下四种形式之一。角色和名称按精确匹配使用；优先选能反映用户所见标签的形式，特殊控件再用测试标识或 CSS。

```json
{"role": "button", "name": "保存我的地图"}
{"label": "地图名称"}
{"test_id": "my-map-save"}
{"css": "#my-map-save"}
```

这是四个独立写法示例，不是一个完整 JSON 文件。配置不接受任意 JavaScript、未知键、重复 JSON 键、空值或明显未填写的占位内容。某个按钮与多个元素匹配时，应收窄定位，不依靠“取第一个”隐藏歧义。

### 适配层观察哪些界面

| 语义键 | 当前要求 |
|---|---|
| `map_editor`、`map_input`、`map_apply` | 原地图编辑的 `<details>`、字符地图文本框和应用按钮 |
| `map_title`、`name` | 当前地图的可见标题及可编辑名称控件 |
| `archives`、`load` | 原生 `<select>` 存档列表和加载按钮；按选项标签选择，不要求 `value` 等于名称 |
| `save`、`delete`、`import_file`、`export_file` | 保存、删除、文件输入和单张地图导出入口 |
| `feedback`、`error` | 用户反馈区域；`error` 应仅在错误状态可见且非空，不能直接映射到一直显示正常提示的元素 |
| `confirm_dialog`、`confirm_yes`、`confirm_no` | `confirmation: "dom"` 时必需；选择 `native` 时移除这三个键 |
| 原功能回归控件 | 模板中的 `presets`、算法、回放、地图格子、画板、分类和样本控件；若改过原页面，也要更新映射 |

运行器通过页面动作和可见 DOM 观察结果，不要求读取名为 `grid` 的全局变量，也不规定本地存储必须是教师所用的数组结构。适配配置仍需完整；`--cases` 选择本次执行的行为检查，不免除必要的配置核对。

第一版地图观察器同时核对字符地图文本框与 `grid_cells` 的 `aria-label`，沿用原工程的“第几行第几列、是否机器人、墙／普通地面／S／G／成本数字”语义。只改 CSS 映射不能适配已完全改写这些标签语义的地图渲染器；需要补充观察适配并重新验证断言，不能绕过网格检查。

若作品使用原生确认，测试会在触发动作前注册对话框处理；选择 DOM 确认则使用实际按钮。不要把“请求删除”直接映射为已确认删除，也不要为方便测试关闭确认步骤。

DOM 确认可通过实际 Tab、Enter、Space 测试；原生浏览器窗口由 Playwright 的 accept／dismiss 接口处理，这只证明接受／取消行为，**不证明真实键盘能操作原生窗口**。选择 `native` 时还须人工检查原生确认的键盘过程。

## 3. 在另一个终端运行

保持自己的服务运行，在相同作品根目录执行：

```bash
python -m acceptance.robot_portfolio --url http://127.0.0.1:8765 --adapter classroom/robot_portfolio/student/my-acceptance.json --source-root . --output reports/my-acceptance-001
```

`--output` 必须指向新的目录；已有结果不会覆盖。重跑时换成 `reports/my-acceptance-002` 等新名字，保留失败和修复后的两份记录，防止把旧通过报告与新失败混在一起。

分阶段只检查 A01、A02 时使用：

```bash
python -m acceptance.robot_portfolio --url http://127.0.0.1:8765 --adapter classroom/robot_portfolio/student/my-acceptance.json --source-root . --output reports/my-acceptance-003 --cases A01,A02
```

其他编号仍出现在报告中并标记 `not_run`。子集通过不能写成“完整 A01—A12 已通过”。修复后应再运行全部检查和原项目回归测试：

```bash
python -m unittest discover -s projects/robot_playground -p "test_*.py" -v
```

运行器为各场景建立新的浏览器上下文；A12 用另一个空上下文导入真正下载的文件。不会复用你日常浏览器中的已有记录来凑出结果。A09 只在这个测试上下文中，对声明的存储键制造写入失败或坏历史；不要在自己的常用浏览器填满磁盘或清空全部站点数据来模拟异常。

## 4. 每个 A 编号检查什么

任务书是学生功能契约。自动检查的可观察范围如下，完整输入和断言保留在 `cases.py` 中；教师实现额外采用的存储结构或 UI 命名不是学生要求。

| ID | 自动检查重点 |
|---|---|
| A01 | 保存合法地图，改变当前地图、刷新并重新加载，核对名称和网格 |
| A02 | 空白名称、41 码点拒绝及合法名称边界；失败保留已有状态 |
| A03 | 同名时明确拒绝／改名提示或确认覆盖；取消不得改写原记录 |
| A04 | 取消删除后记录仍可加载，确认操作只影响目标地图 |
| A05 | 非法 UTF-8、JSON、导入名称、版本或顶层结构被拒绝；可读错误，旧状态不变；合法 U+FFFD 名称可导入并刷新加载 |
| A06 | 非法地图结构被拒绝，合法几何边界与无解地图按契约处理 |
| A07 | 16,384 字节与 16,385 字节边界，观察超过上限时是否在解析前拒绝 |
| A08 | 类似 HTML 的名称作为普通文本显示，不出现名称派生的 HTML 或脚本执行 |
| A09 | 存储失败和坏历史的恢复行为；不崩溃、不伪报成功，比较原始存储字符串 |
| A10 | 键盘完成保存、选择、加载及 DOM 确认，检查可识别标签；原生确认键盘和焦点的实际视觉表现另行复核 |
| A11 | 原求解、回放、地图及符号分类流程，保留预测后的明确确认 |
| A12 | 实际下载单地图 JSON，在空上下文导入、加载，检查名称与网格往返 |

**A07 保持“解析前拒绝”。** 它不要求学生像教师实现一样在读取文件前拒绝。当前探针观察页面主上下文的 `JSON.parse`；自定义解析器、Worker 或其他绕过该探针的路径须结合学生代码、断点或自编测试补证，不能因探针未观察到解析就宣称所有路径均已证明。

**A05 区分文件字节和解码后的字符。** 不能因为宽松解码后的文本能通过 `JSON.parse`，就认定原文件是合法 UTF-8。测试使用名称中含非法字节、其他结构合法的输入，并检查失败后原始存档和页面不变；同时接受合法编码的 `�`（U+FFFD）名称，避免误拒合法字符。原始学生包的 `fixtures/invalid-utf8.json` 可用于手动复现，请直接导入，不先经编辑器重新保存。技术依据见 [S6](SOURCES.md)。

**A09 不规定教师的存储封装。** 当前自动输入覆盖保存、导入、确认删除，以及启用覆盖策略时的覆盖写入失败；还会把已写入的键逐个替换为无法解析的 JSON，要求页面可用、不抛未处理异常、不改写原始历史字节。损坏历史可明确提示或忽略坏记录，按任务书保留这两种策略。此用例不假定内部容器是数组，也不要求学生复制教师的混合坏记录恢复方式；它没有模拟读取 API 本身抛异常。

**A10 保留人工复核。** 自动键盘动作和标签检查不足以判断焦点环在实际配色、缩放和窄屏上是否清晰；原生确认窗口也须人工键盘操作。按报告在真实浏览器观察焦点、标签和主要操作，并填写证据。工具不宣称完成 WCAG 合规审计。

## 5. 怎样读取结果

输出目录包含 `report.json` 与便于阅读的 `summary.md`；进入页面后发生失败时，会尽可能保存截图。A10 运行到焦点检查时另留截图供人工复核，A12 实际导出的文件也保留在本次目录。配置或浏览器前置条件阻塞时可能尚无页面，缺截图不能被改写为已执行业务检查。

| 退出码 | 含义 | 接下来做什么 |
|---|---|---|
| `0` | 本次所选自动检查完整执行并满足断言 | 核对是否选了全部编号，再补报告列出的人工复核和独立反例 |
| `1` | 已执行检查出现业务断言失败或运行错误 | 根据实际场景、异常和截图定位，保留失败，再在新目录回归 |
| `2` | 配置、环境或前置条件阻塞 | 处理明确原因；不能把未能执行的场景记为通过 |

报告保留完整 A01—A12 表、所选编号、实际执行情况、未运行项及 `manual_review`。`all_contract_automated_pass` 只讨论全部编号的自动检查；即使为真，也不是全部人工要求完成或已经给分。计数、跳过或预期编号不一致时，不可声明完整自动检查通过。

核对报告时先看对象：请求及实际 URL、适配配置摘要、源码根目录、可取得的 Git 来源和每个声明资产的 SHA-256。`source_files` 只证实**列出的 HTTP 响应字节与本地文件一致**；没有认证未列出的资源、服务后端或某个学生的原创贡献。Git 有未提交变化或来源未知时如实保留该状态，不把提交号当作工作树的完整快照。

学生模式发现已知教师页面标识会阻止误用。此措施防止常见的地址填错，不是对恶意改写目标的身份认证，更不是防作弊机制。教师校准必须显式使用 `target_kind: "reference"` 配置并增加 `--allow-reference`；校准报告只能说明参考目标的结果，不能转记为学生作品完成。

### 常见阻塞与诊断

| 现象 | 先检查什么 |
|---|---|
| 提示 TODO、缺键或未知配置 | 是否复制模板后按实际实现填完；JSON 不支持注释或重复键 |
| 连接失败、HTTP 资产不一致 | 服务是否仍运行、端口是否正确、`--source-root` 是否真是这个服务使用的作品；检查新增脚本是否列出 |
| 定位不到控件或匹配多处 | 在实际页面核对标签、role、test id 或 CSS；区分配置错误与尚未实现的功能 |
| 导入失败后检查超时 | 检查真实错误提示、异步操作是否完成和 `error` 的匹配条件；不要直接调大超时掩盖缺陷 |
| 一直只有教师结果通过 | 核对启动命令、学生 URL 和配置中的 `target_kind`，不添加 `--allow-reference` 来“解决”学生失败 |

最后把自动报告和人工复核填入自己的 `MY-SUBMISSION.md`。同伴或教师仍须独立选择至少三个反例，保留其中失败、未运行或环境阻塞的事实，并检查个人对修复理由的解释。

## 6. 教师维护：验证验收器本身

以下命令在完整仓库根目录执行；学生 ZIP 不包含验收器自身的校准夹具和教师答案：

```bash
python -m unittest acceptance.robot_portfolio.tests.test_runner -v
python -m unittest acceptance.robot_portfolio.tests.test_integration -v
```

第一条使用标准库检查报告、目标配置、零测试、跳过及部分运行等情况。第二条需要上述浏览器依赖与 Git，自动使用随机本机端口和临时副本。它验证三组完整 A01—A12：原教师适配、改名控件／对象容器／私有 JS 状态、原生确认／拒绝重名。变体还覆盖缓存存储方法、成功操作更新元数据、中文否定错误提示和坏历史只读模式；这些都是验收器的校准输入，不是真实学生试教结果。

负对照要求原始学生起点不能通过、错误 URL／源码不一致／误指教师页必须被阻止，以及现有存储故障补丁使 A09 失败、反向应用后恢复通过。编码负对照另在临时教师副本中放宽 UTF-8 解码，要求 A05 抓住错误，恢复严格解码后再通过。这里的“对照测试通过”包含预期业务失败，不能把故障副本的 A05 或 A09 写成已通过。

导航回归另挂起一张同源图片，验证首次打开与刷新在必要控件和地图就绪后可以继续，不强等整页 `load`。它保留原超时和全部就绪断言，不通过延长等待或跳过状态检查掩盖失败。完整工具集成套件现有 9 个方法，与学生的 12 个 A 编号是不同计数。

`Student target acceptance harness` 工作流执行这些检查；浏览器对照报告作为 `student-acceptance-harness-evidence` 保存 14 天。实际结果以对应提交的 Actions 为准。普通本机自测默认清理临时报告；如需保留，在运行第二条命令前设置 `ROBOT_ACCEPTANCE_TEST_EVIDENCE` 为一个新的证据目录。每次使用新目录，避免和旧结果混合。
