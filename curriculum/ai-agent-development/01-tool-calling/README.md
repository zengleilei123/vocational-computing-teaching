# 实训 01：理解工具调用型智能体

## 实训目标

完成后能够：

- 说明工具注册表的作用
- 解释用户请求如何路由到不同工具
- 区分工具选择、参数验证、工具执行和结果返回
- 运行单元测试并解释错误处理
- 说明本示例为什么还不是真正的 LLM 智能体

## 环境

- Python 3.10+
- 仅使用 Python 标准库
- 不需要 API Key，不访问网络

## 运行

在仓库根目录运行：

    python curriculum/ai-agent-development/01-tool-calling/agent.py

运行测试：

    python -m unittest discover -s curriculum/ai-agent-development/01-tool-calling -p "test_*.py"

## 架构

    用户请求
       |
       v
    确定性请求路由器
       |
       v
    工具白名单 / 参数校验
       |
       +--> calculator 工具
       |
       +--> course_faq 工具
       |
       v
    统一结果格式 + 终止

本实训用简单规则实现决策，让初学者先看懂完整控制流。真实 LLM 智能体会让模型根据工具说明选择工具并生成参数，但模型不能绕过工具白名单和参数校验。

## 支持的示例请求

- 计算 12 * (3 + 4)
- 查询 Python 课程需要哪些先修知识
- 你好

计算器只允许有限的算术表达式，不使用 eval 执行任意代码。

## 学生任务

### 基础任务

1. 运行所有示例。
2. 阅读 agent.py，画出一次请求的执行流程。
3. 增加一个课程 FAQ 条目，并编写测试。
4. 为无法识别的请求设计更清楚的提示。

### 提高任务

1. 增加一个只读的单位换算工具。
2. 为工具输入和输出定义明确的数据结构。
3. 为工具执行增加统一错误结果。
4. 增加一项测试，证明不支持的函数调用不会执行。

### 挑战任务

设计一个模型无关的 Planner 接口，并说明如何让真实 LLM 返回结构化工具调用请求。不要将模型返回的工具名称直接执行；必须先校验是否在白名单中。

## 验收标准

- 所有测试通过
- 非法表达式被拒绝
- 未知工具不会执行
- FAQ 未命中时返回明确的未找到信息
- 学生能解释规则路由与 LLM 规划器的差别
- README 能让另一名学习者在本地复现

## 讨论题

1. 为什么简单 FAQ 不一定需要智能体？
2. 如果工具可以发邮件，为什么不能让模型直接决定并发送？
3. 工具返回错误时，应该终止、重试还是请求人工帮助？
4. 如何设计测试来检查模型是否在不需要时调用工具？
