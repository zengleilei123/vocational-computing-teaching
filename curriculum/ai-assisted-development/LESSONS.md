# 六个单元：从 AI 体验到可交付功能

> 6 × 4 学时 = 24 学时，每学时 45 分钟。学生应有 [先修基础](README.md)。这是授课设计，尚未开展真实课堂试教。完整作业约束见 [任务书](CAPSTONE.md)。

教师首次授课可使用[两学时启动活动](../../classroom/robot_portfolio/README.md)，作为单元 1 的前两学时，不额外增加总课时。学生全程填写[任务卡](../../classroom/robot_portfolio/student/WORKBOOK.md)与[提交模板](../../classroom/robot_portfolio/student/SUBMISSION.md)；先修不足时按[诊断题](../../classroom/robot_portfolio/student/DIAGNOSTIC.md)补学。

## 单元 1：先让想法可见，再定义完成（4 学时）

开场让学生用 AI 改一个低风险界面细节，如地图名称说明或帮助文本；目标是尽快看到变化，不以生成速度计分。随后教师提出一个反例：刷新页面之后，地图为什么丢了？

第 1 学时运行基线并记录入口；第 2 学时两人访谈，把“做一个酷炫地图工具”改成具体用户故事；第 3 学时写保存、加载、损坏数据和重复命名的验收条件；第 4 学时交换需求，另一组只按文档判断怎样才算完成。

交付 `brief.md`：用户、痛点、功能、非目标、输入输出、3–5 条可测条件。学生必须说明不做账号、云同步和公开分享，避免 AI 擅自扩张范围。

## 单元 2：让 AI 读对上下文（4 学时）

让 AI 只读指定目录，画出一次“点击求解”的文字调用链：HTML 控件 → app.js → POST `/api/solve` → server.py → engine.py → JSON → 页面结果。学生逐处打开文件核对，不能把 AI 编造的文件当事实。

第 1 学时定位 3 个真实文件；第 2 学时观察 Network 中请求、响应和状态码；第 3 学时比较两种方案：浏览器本地存档与后端数据库；第 4 学时选定当前本地单人范围，写分步计划、影响文件和风险。

交付 `plan.md` 和 3 个自己核实过的代码位置。故障练习：候选方案引用不存在的数据库接口，学生要先核对而不是照抄。

## 单元 3：小步实现，不一键接受全部代码（4 学时）

按最小纵向切片迭代：名称输入和空态 → 保存一张地图 → 刷新后加载 → 清单选择和删除。每步先确认预期行为，再请 AI 修改限定文件；没有必要不得改变地图求解算法。

第 1 学时查看基线 Git 状态并建自己的分支；第 2 学时完成纯数据校验与保存；第 3 学时接入页面并审查 diff；第 4 学时同学验收且学生解释数据流。

交付小范围 commit 和对应测试。参考命令 `git status`、`git diff --stat`、`git diff`；提交前逐个确认文件。不要默认 `git add .` 把无关文件、导出数据或密钥一起提交。

## 单元 4：开发不是只有正常路径（4 学时）

第 1 学时输入非法地图 JSON、缺少起终点、超大文件；第 2 学时测试浏览器存储异常和损坏的旧记录；第 3 学时在同源本机环境检查接口报错，保持后端约束；第 4 学时保留当前已加载地图，验证失败操作没有半途污染状态。

交付正常、边界、失败三类验收表。故障练习：候选补丁只禁用按钮，却删掉服务端大小限制。学生必须拒绝这种“界面能用但保护被绕开”的改法。

不能为图方便修改跨来源/本机限制、绑定公网、关闭浏览器安全功能。真实后端持久化放在开发桥接单元的 SQLite 扩展，不强塞进所有学生的 24 学时作业。

## 单元 5：AI 会出错，测试也可能错（4 学时）

教师在隔离学生分支提供一个已知故障的候选 diff，例如：把加载失败时保留当前地图改成直接清空；仅验证导出成功而不验证再导入。不要故意污染共享主分支。

第 1 学时用输入和步骤复现；第 2 学时写预期与实际、阅读浏览器报错；第 3 学时请 AI 提出最小修复并人工审查；第 4 学时跑回归、复测页面、记录失败如何消失。

额外审查：AI 是否删除断言、把错误吞掉、扩大文件访问、硬编码密钥、引入无理由的依赖？只靠 AI 同时写实现和测试还不够，至少保留教师/同学独立提出的反例。连续两次修改未改善时暂停生成，重新定位，不以轮数和 token 消耗计分。

## 单元 6：别人能用，自己能解释（4 学时）

第 1 学时在干净副本中按 README 运行；第 2 学时交换验收，检查桌面和窄屏；第 3 学时写 PR 和 AI 使用记录，只保留脱敏关键片段；第 4 学时个人答辩与现场小改。

个人现场题：将名称上限从 40 改为 30 并更新对应边界；或解释“刷新后存档仍在，但更换浏览器不能同步”的原因。允许查官方文档，不允许直接让 AI 代答这一小段基础检查。无障碍或其他学习支持按学校规则提供等价方式。

## 基线命令（从仓库根目录）

```bash
python -m projects.robot_playground.server --port 8765
python -m unittest discover -s projects/robot_playground -p "test_*.py" -v
node --check projects/robot_playground/static/app.js
```

服务启动后在浏览器打开 `http://127.0.0.1:8765`。Node 用于开发期语法检查，运行课堂页面并不要求 Node。可选端到端检查按机器人项目 README 安装 Playwright，并运行 `python -m projects.robot_playground.tools.browser_smoke`。

现有基线测试不会自动覆盖学生新加的存档功能；必须补相应测试与人工验收。不能因为旧测试全部通过就声明新需求已通过。
