# AI 协作工作卡：先想清楚，再让工具加速

> 以下是可改写的教学提示，不是保证模型行为的安全措施。权限、测试、分支和人工审查必须独立存在。不要复制密钥、真实学生记录或企业材料进提示。

## 卡 1：澄清需求，不急着写代码

```text
我要为本仓库机器人挑战场增加“地图本地存档”。
用户：在自己电脑上学习的学生。问题：刷新后设计丢失。
只做：命名、保存、加载、删除前确认；不做账号、云同步和公网分享。
请先列出不明确的需求，并给出可测试的验收条件。
先不要改代码。把建议与已经在仓库实现的能力分开。
```

人工检查：我是否真正需要每个功能？描述中是否偷加外部服务、登录、数据库或付费 API？

## 卡 2：给上下文和约束

```text
先读取 projects/robot_playground/README.md、server.py 和 static 目录。
说明地图从界面到 /api/solve 再到 engine 的路径，引用真实文件位置。
本次只改地图存档，不改变算法、显式动作确认、同源限制和已有测试。
列出计划修改的文件、数据契约、失败路径和验证命令。
缺少事实时明确说缺少，不猜测接口。
```

人工检查：打开 AI 引用的代码核对；确认它读取的是本次分支，而不是旧版或另一个项目。

## 卡 3：一次只实施一个可验收切片

```text
按已确认计划，仅完成“保存一张合法地图并刷新恢复”。
先补能证明需求的测试或可执行验收，再实现。
保留已有失败断言；不要为了测试通过删约束。
结束时给出实际 diff 摘要、实际执行命令与结果、尚未验证部分。
不要提交、推送或部署，等待我审查。
```

学生审查后自行决定是否提交。指定“先写测试”不自动意味着测试有效；查看测试是否真的覆盖需求和反例。

## 卡 4：报错不是一句“帮我修一下”

```text
预期：损坏 JSON 导入失败后，当前地图保持不变。
实际：页面清空。
复现：先加载默认地图，再导入内容为“{”的本地测试文件。
附：相关文件、脱敏后的控制台错误、最近一次小改动。
请先定位根因和一个最小反例，再提出最小补丁。
不要重写全项目，不要隐藏异常或放宽校验。
```

两次尝试都没改善时，停止扩大上下文，缩成最小复现；由学生/教师决定下一步。不存在必须消耗多少轮 AI 才算努力的要求。

## 卡 5：要求交付证据，而不是赞美输出

```text
请按验收表逐项报告：已验证/未验证/失败。
每个已验证项附实际命令或浏览器操作、输入、观察到的输出。
说明是否使用真实模型、是否访问网络、是否有费用。
不要把单元测试通过写成整站可上线，也不要虚构截图或日志。
```

## 卡 6：diff 审查六问

是否只改了授权范围？是否删除测试/放松断言？是否新增网络请求或依赖？密钥和个人信息是否进入代码/日志？前端校验是否替代了后端保护？文档是否把未实现能力写成已完成？

提示文件（AGENTS.md、CLAUDE.md、工具规则）只能表达约定，不能代替强制权限。Cursor checkpoint 是局部回退便利，不代替 Git 历史。[S3–S5](SOURCES.md)

## Git 与回退演练

在自己的练习分支，先 `git status` 确认工作区，再查看 `git diff`。已提交的错误可以通过 `git revert <自己的错误提交>` 生成反向提交；revert 可能发生冲突，应先阅读状态并请教师协助。未提交修改先复制/保存所需内容，再决定丢弃范围。默认不使用 `reset --hard` 或 force push，不重写同学历史。

把数据库/本地存档的恢复与代码回退分开：恢复代码不保证数据自动恢复，部署回退也不是关闭本地进程就完成。
