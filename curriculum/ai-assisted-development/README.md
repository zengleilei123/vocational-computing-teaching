# AI 辅助应用开发：Vibe Coding 项目实训

> 状态：课程设计、学生任务书与课堂材料，尚未真实试教。学生起始工程中的地图存档仍待实现；教师 V1/V2 参考、独立验收与故障练习使用单独入口。面向高职计算机类专业；不绑定某地区、学校或商业工具。

## 课程定位

让学生借助 AI 将一个小需求做成可解释、可测试、可复现的功能。允许快速探索，但正式交付必须有需求、改动审查、测试和回退记录。不是“无需基础、看不懂代码也能放心上线”的承诺。

特别区分：**智能体开发课**研究应用怎样使用模型和工具；**本课**研究开发者怎样使用 AI 编写、修改、调试和交付软件。一个不含任何大模型接口的预约网站，也能作为本课作品。

## 与基础课程的关系

建议组织一个 **72 学时的项目强化单元**：12 学时实用算法回顾 + 36 学时应用开发 + 24 学时 AI 辅助开发。每学时按 45 分钟计算；这是已有程序设计基础后的建议组合，不是完整专业培养方案，不替代学校的数据结构、网络或其他必修课程。

## 先修诊断

学生在不请求 AI 直接给答案的情况下，应能够：

1. 读懂一个含函数、循环和字典的小程序，修改一个简单条件。
2. 区分浏览器页面、服务端代码、JSON 数据和数据库。
3. 根据 README 启动已有项目，找到一次错误的文件与行号。
4. 运行一条测试命令，理解通过、失败、没有发现测试的区别。

四条要求对应[四个可操作的小任务及补学动作](../../classroom/robot_portfolio/student/DIAGNOSTIC.md)。未达到的学生先补对应知识并重做，再进入主任务；仍可参加教师组织的 AI 体验活动，但不能把体验当作独立开发能力。

## 24 学时课程大纲

| 单元 | 学时 | 学生交付 | 不可省略的人工检查 |
|---|---:|---|---|
| 1. 从想法到验收 | 4 | 用户故事、非目标、3–5 条验收条件、基线运行记录 | 学生能解释要解决谁的问题 |
| 2. 读懂仓库并规划 | 4 | 一次请求的调用链、文件范围、分步修改计划 | 找到真实入口，不编造文件/API |
| 3. AI 辅助小步实现 | 4 | 地图保存/加载功能的第一版及小范围 diff | 区分状态、界面、存储和校验 |
| 4. 接口与异常行为 | 4 | 合法与非法 JSON、失败提示、重复提交处理 | 前端禁用按钮不等于后端约束 |
| 5. 调试、测试与安全 | 4 | 失败复现、回归测试、一次越界需求拒绝说明 | 不删测试、不放宽约束换取绿灯 |
| 6. 交付与现场修改 | 4 | PR、运行说明、验收报告、个人讲解 | 同学复现，学生独立解释并改一处逻辑 |
| 合计 | 24 | | |

每个单元建议约 1 学时讲解/演示、3 学时练习与反馈；根据学情调整。课程目标是做完一个受控功能迭代，不是一次覆盖前后端全栈和所有 AI 框架。

## 工具与资源

选一种教师可统一支持的工具作为主工具即可，例如 Cursor 或 VS Code + GitHub Copilot；命令行工具放在进阶路径。不比较“谁永远最强”，也不要求同时购买多种订阅。所有工具都走相同的需求、diff、测试、回退流程。

联网 AI 工具的账号、额度、地区可用性和学校许可需课前核实。无法访问服务时，用教师准备的脱敏候选补丁进行审查与验收练习，评分标准相同；不要绕过访问限制，不把付费额度当作学生能力差异。

机器人挑战场本身离线运行；AI 编程助手通常会将选定上下文交给服务方，两者不是同一个数据边界。只使用本仓库公开代码和合成样本，不发送真实学生资料、企业代码或密钥。

## 统一工作流

理解需求 → 确认验收 → 读取代码 → 写计划 → 一次小改动 → 审查 diff → 运行测试和实际界面 → 提交/回退 → 记录不足。

AI 的完成说明不是验证证据。CI 通过也只代表现有检查通过，不代表没有安全漏洞或教学效果已经成立。公开部署、删除数据、改权限、引入付费服务需额外授权，不在默认学生任务范围。
