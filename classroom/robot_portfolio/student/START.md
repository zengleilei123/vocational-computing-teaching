# 从这里开始：15–20 分钟跑通机器人项目

学生起点已经支持地图编辑、求解、回放和实验导出；**命名保存、加载存档和地图 JSON 导入由后续任务实现**。本阶段只需要 Python 3.10+、浏览器和文本编辑器，离线运行，无需 AI 账号或付费订阅。首次安装 Python 或获取文件的时间不计入下面的 15–20 分钟。

## 先确认你拿到的是哪种材料

- 教师发的 `robot-student.zip`：完整解压到自己的练习目录，保留内部目录结构，再打开这个目录的终端。
- 完整教学仓库：可以直接运行学生起点；需要输入样例时，先生成并解压学生包。

**工作根目录**是同时能看到 `projects/`、`tools/`、`classroom/` 的目录。后面的命令均在这里执行。编辑器只打开了 `student/` 或 `static/` 时，要先返回根目录。不要在压缩包预览窗口中运行，也不要直接双击 `index.html`。

完整仓库中的 `fixtures/` 不预先存在。需要样例时，在完整仓库根目录运行：

```bash
python tools/robot_classroom.py bundle --output dist/robot-student.zip
```

将生成的 ZIP 解压到一个新的练习目录，再在该目录找 `fixtures/README.md`。这些文件只是后续验收输入，起始页面暂时没有导入它们的功能。输出 ZIP 已存在时，工具会拒绝覆盖；保留旧包，改用新的输出文件名。

包内 `MANIFEST.json` 记录发包时的来源和哈希，不会自动记录后续修改。ZIP 不含 Git 历史、教师实现或故障答案。

## 第 1 步：选对 Python 命令（约 2 分钟）

Windows 建议使用 PowerShell；doctor 给出的 `Set-Location` 切换目录与 `&` 启动命令按 PowerShell 语法复制执行。

先运行：

```bash
python --version
```

读实际输出，确认版本至少为 3.10。如果这条命令不可用，按系统尝试：

| 系统 | 尝试的命令 | 后续怎样替换 |
|---|---|---|
| Windows | `py -3 --version` | 例如把 `python tools/robot_classroom.py ...` 改成 `py -3 tools/robot_classroom.py ...` |
| macOS / Linux | `python3 --version` | 后面的 `python` 统一换成 `python3` |

选定一个确实达到版本要求的命令，后续保持一致。找不到合适的 Python 时，记录屏幕提示，请教师按机房流程准备解释器；环境检查工具本身也需要 Python，不能替你安装它。

## 第 2 步：检查环境（约 2 分钟）

```bash
python tools/robot_classroom.py doctor --port 8765
```

阅读每项结果和下一步提示。它检查解释器、运行文件、目录及回环端口，不联网、不安装依赖、不改系统配置。Node 和 Playwright 属于可选开发工具；基础课堂运行不要求它们。Chromium 没有被此工具实际验证，不能由此宣称浏览器验收已通过。

端口检查只代表检查当时的情况。若提示 8765 被占用，先确认是否是自己之前启动的服务。不要关闭不认识的进程；可以请教师协助，或选择另一个端口，并在诊断、启动和浏览器地址中使用同一个端口号。

## 第 3 步：启动并找到页面（约 3 分钟）

在终端 A 运行：

```bash
python -m projects.robot_playground.server --port 8765
```

保持这个终端打开，在浏览器进入 **http://127.0.0.1:8765**。应当看到“校园机器人挑战场”、字符地图和方向控制。服务保持运行时终端不返回新的命令提示符是正常现象；结束时在终端 A 按 Ctrl+C。

## 第 4 步：先预测，再操作（约 5 分钟）

先在纸上写一句预测：“步数最少的路线是否一定最省能耗？”稍后转入第 6 步建立的 `MY-SUBMISSION.md`。然后依次完成：

1. 保持第一张预设地图，手动移动一次，读出步数和能耗。
2. 点击“回到起点”，分别运行 BFS 和 Dijkstra，再拖动回放滑块。
3. 核对这张固定地图的结果：BFS 为 6 步、能耗 46；Dijkstra 为 10 步、能耗 10。这里的能耗是格子成本的模拟值。
4. 切换到“不可能任务”对应的第三张预设地图，运行 BFS，记录未到达时页面怎样说明原因。

保留一条实际观察和一处与你预测不同的结果。若结果不同，先检查自己是否修改过地图、是否切换了预设，再记录现象。不要为了对上示例数字改评测器。

## 第 5 步：运行基线测试（约 3 分钟）

另开终端 B，确认仍在同一个工作根目录，执行：

```bash
python -m unittest discover -s projects/robot_playground -p "test_*.py" -v
```

本次发放的未修改起点包含 **37 项测试**。检查实际运行数量、最后的 `OK` 或 `FAILED`，并保存原始输出。`Ran 0 tests` 即使同时出现 `OK`，也没有验证这个项目。

测试包含真实本机 HTTP；机房策略禁止本机端口等情况应如实标成“环境阻塞”，由教师协助判断。不要删测试、改断言或关闭浏览器保护来取得通过。

## 第 6 步：留下首次成功证据（约 2 分钟）

将 [提交模板](SUBMISSION.md) 在 `classroom/robot_portfolio/student/` 同目录复制为 **`MY-SUBMISSION.md`**，保留原模板。这个不同名称在 Windows 上也能并存，副本中的相对链接仍有效。随后填写：

- Python 命令与版本、浏览器、工作目录、页面 URL；
- 运行前预测、实际结果和失败现象；
- 基线测试的实际命令、运行数量、状态、输出位置及下一步。

环境诊断成功、旧测试通过，分别说明环境和旧行为得到检查；新增地图存档功能仍需你自己实现和验收。**教师参考实现的测试固定运行教师应用，不是学生作品的通用评分器。**你的新增验收必须指向自己的文件和运行入口。

## 遇到问题时先查这里

| 看到的情况 | 下一步 |
|---|---|
| 找不到 `robot_classroom.py` 或 `projects` 模块 | 检查解压完整；回到同时包含 `tools/`、`projects/` 的根目录，使用给出的命令 |
| 地址已被使用 / 端口占用 | 确认自己的已有服务；更换端口时同时修改诊断命令、启动命令和 URL |
| 浏览器无法打开页面 | 确认终端 A 仍在运行、使用 `http://127.0.0.1`、端口一致；保存终端实际错误 |
| 看不到保存或导入控件 | 这是尚待实现的学生任务，按工作簿逐步增加 |
| 测试发现 0 项 | 核对工作目录和 `-s`、`-p` 参数，记录原输出后再重跑 |

完成后进入 [四项先修诊断](DIAGNOSTIC.md)，再按 [五阶段工作簿](WORKBOOK.md) 开发。完整功能约束见 [综合作业任务书](../../../curriculum/ai-assisted-development/CAPSTONE.md)，原项目说明见 [机器人 README](../../../projects/robot_playground/README.md)。
