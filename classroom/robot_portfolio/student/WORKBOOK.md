# 我的地图作品集：五阶段工作簿

先完成 [START](START.md) 和 [DIAGNOSTIC](DIAGNOSTIC.md)。目标是在自己的学生工程中完成 V1/V2：命名、保存、列表、加载、删除确认、单张地图 JSON 导出与导入。完整契约以 [CAPSTONE](../../../curriculum/ai-assisted-development/CAPSTONE.md) 为准；本工作簿不提供存档实现或参考答案。

每个阶段按“预测 → 运行观察 → 解释 → 小步修改 → 独立完成”的顺序推进。先写预期，再操作；先读实际文件，再接受建议。AI 可用于讨论和解释，无 AI 时使用项目源码、[工作卡](../../../curriculum/ai-assisted-development/WORK-CARDS.md)与同伴交流，交付标准相同。

将 [SUBMISSION.md](SUBMISSION.md) 在 `classroom/robot_portfolio/student/` **同一目录**复制为 **`MY-SUBMISSION.md`**；不同文件名在 Windows 上也能保留原模板，相对链接仍有效。每次只改一个能验收的小目标，记录文件、理由和实际结果；保留起点副本以便比较或恢复。

三人小组可轮换操作、观察和验收角色，每阶段每人都要独立解释一次。得到提示不扣去学习机会，但不能把同伴操作记录成自己独立完成。

| 阶段 | 最小产出 | 主要 A 编号 |
|---|---|---|
| 1. 名称与地图契约 | 明确的数据说明及可重复的合法／非法输入检查 | A02、A05、A06 |
| 2. 保存后刷新再加载 | 一张地图真正持久化；写入失败能够被识别 | A01、A09 |
| 3. 管理多张地图 | 列表、明确覆盖、确认删除、安全显示与键盘操作 | A03、A04、A08、A10 |
| 4. 交换作品 | 单张地图导出、严格导入、失败保留状态 | A05、A06、A07、A12 |
| 5. 独立验收与交付 | 原功能回归、三个独立反例、恢复记录与个人讲解 | A11，并复查 A01–A12 |

阶段间可以反复返回。尚未完成的功能标为“未运行”或如实记录已观察到的失败；V3 数据库扩展不属于这五阶段的必做范围。

## 输入样例在哪里

以下 `fixtures/` 文件只在**生成后解压的学生包根目录**中出现。完整仓库使用者先按 [START](START.md) 运行 `bundle` 并解压，或从包内复制样例到自己的测试目录；不要把“仓库里暂时没有这个目录”误认为产品故障。先读包内 `fixtures/README.md`，保留原样例，在副本上制作新反例。

| 文件 | 用途 |
|---|---|
| `fixtures/valid-map.json` | 合法的单张地图，用于保存与交换 |
| `fixtures/invalid-json.json` | 无法解析的 JSON，检查 A05 |
| `fixtures/unknown-version.json` | 不支持的版本，检查 A05 |
| `fixtures/missing-goal.json` | 缺 G，检查 A06 |
| `fixtures/duplicate-start.json` | 重复 S，检查 A06 |
| `fixtures/unequal-rows.json` | 行宽不同，检查 A06 |
| `fixtures/html-name.json` | 名称含类似 HTML 的文字，检查 A08 |
| `fixtures/unicode-name-40.json` | 40 个 Unicode 码点的名称边界，检查 A02 |
| `fixtures/boundary-16384.json` | 正好 16,384 字节，检查 A07 的可接受边界 |
| `fixtures/oversize-16385.json` | 16,385 字节，检查 A07 的拒绝边界 |

样例文件没有替你运行断言，也不包含学生功能实现。遇到文件被拒绝时，要观察是哪条约束触发、状态是否保持，不能把“出现错误提示”作为唯一判断。

## 阶段 1：先说清楚什么数据可以进入作品集

读任务书中的 `version/name/grid` 对象，以及原 [engine.py](../../../projects/robot_playground/engine.py) 的地图校验。用一张三行地图 `S..` / `.#.` / `..G` 和一个自拟名称开始。

你要写明：字段类型、允许字段、名称修剪和码点长度、地图行列范围及符号约束。原 engine 要求 **3–20 行、3–20 列、等宽、唯一 S/G**；合法无解地图仍属于有效地图。约束应来自这些实际材料。

产出你自己的可重复检查方式，可以是自动测试，也可以是逐项输入、明确预期和实际的人工检查。先让合法输入被接受、非法输入被拒绝，再接复杂界面。

### 必试反例

- A02：空白名称；40 个码点的名称；在其副本中再加一个码点得到 41。
- A05：版本为字符串 `"1"`、布尔值 `true` 或未知值；缺字段或多字段。
- A06：缺终点、重复起点、不等宽；补充 2 行和 21 行的地图。

只统计 `.length` 是否足以表示所有名字的码点数，需要你自己用样例验证。不要把地图无解当作结构校验失败。

提示 1：把一个失败输入与任务书逐字段比较。提示 2：记录“读入的数据”和“允许的范围”，找出首次不一致的位置。提示 3：先缩小到一条规则及一对仅有一个差别的输入，再请同伴检查预期是否合理。

自己解释：为什么版本 `1` 与 `"1"` 需要区分？一张地图没有可达路线，和地图不等宽是不是同一种错误？

**阶段证据：**数据契约说明、至少一个合法边界和两个反例、实际输出与被检查的代码位置。完成较快者为 20×20 合法边界、非法字符或多字段补独立测试，不提前更改后端规则。

## 阶段 2：一张地图确实保存了，刷新之后还能回来

在自己的界面应用合法地图 A，输入名称并保存；将当前页面改成另一张地图 B，再刷新并加载 A。记录保存前、保存后和刷新加载后的名称与网格。

需要持久化的内容仅为单张地图契约。路线、对比、训练样本和页面临时状态各有用途，不能顺手全部写进存档。你需要自己决定并记录学生实现使用的准确存储键。

写入真的完成之后，页面才有依据报告成功。若同名处理还没做完，先明确拒绝有冲突的保存，并记录未完成项，不能暂时静默覆盖已有记录。

### 必试反例

- A01：保存 A 后将当前地图改为 B，再刷新和加载，确保确实恢复 A。
- A09：用隔离的测试数据模拟写入失败，比较页面提示、当前地图、列表和原始存储字符串。

可以在测试中替换自己的存储依赖，让写入操作抛出异常；也可请教师协助做只针对你的存储键、能够恢复的故障注入。不要用填满磁盘、删除原记录或关闭安全设置制造失败。未能构造这个条件时，如实记录“未运行”及待补步骤。

提示 1：区分页面正在显示的值与浏览器真正保存的值。提示 2：画出刷新前后哪些值会重新建立。提示 3：分别追踪正常和异常两条操作路径，找出哪里获得了“确实写入成功”的证据。

自己解释：界面出现了名称，为什么还需要刷新检查？关闭再打开 Python 服务，与清除浏览器站点数据分别可能影响什么？

**阶段证据：**A01 的实际步骤、存储键、原始字符串和刷新结果；A09 的故障条件、失败前后对照或明确未运行记录。完成较快者补充读取存储异常与坏历史记录的恢复验证。

## 阶段 3：管理多张地图，并把选择权交给用户

准备名称不同的 A、B 两张存档，当前页面另放地图 C。实现可识别的列表、加载、同名选择和删除确认。加载应恢复所选地图并清除不再属于它的旧路线与对比。

同名保存必须让用户明确选择改名或确认覆盖；取消保持已有记录。确认覆盖只改变对应记录。删除前须确认，取消后记录仍在，其他地图也不受影响。

### 必试反例

- A03：第二次保存同名地图，先取消再确认，检查另一个存档完全不变。
- A04：请求删除 A 后取消，再加载 A 核对；确认删除时仅删除目标项。
- A08：使用 `html-name.json` 中的名称，观察列表、标题和确认文字，确保名称被当作普通文本。
- A10：只用 Tab、Shift+Tab、Enter、Space 和必要的方向键完成保存、选择、加载与确认；能看见焦点并识别标签。

覆盖与删除也应复查 A09，不能仅让首次保存处理异常。测试使用完整存储快照，不能只查看列表条数。

提示 1：给每次操作写出“目标记录是谁”。提示 2：列出确认之前、确认之后、取消之后应该保持的值。提示 3：请同伴只用键盘操作，并口述自己知道当前焦点和按钮含义的依据。

自己解释：为什么“已经点过删除按钮”还不等于同意删除？为什么把名称显示为文字也属于功能正确性？名称相同的两次保存，你的界面如何让用户知道影响范围？

**阶段证据：**A/B 两条记录的前后对照、一次取消与一次确认、HTML 名称的实际显示、键盘操作记录。完成较快者检查窄屏和取消后焦点是否回到合理位置，并记录真实结果。

## 阶段 4：导出给同伴，再安全导入回来

导出**当前已经应用的地图和名称**为一个 `version/name/grid` 对象。让同伴在空浏览器配置或独立测试上下文中，运行你的学生作品并导入这个文件，核对名称和每一行网格。

导入应检查真实文件字节数、JSON、字段和地图结构；同名导入也须明确选择。超过 16 KiB 的文件在解析前拒绝，严格上限是 **16,384 字节**。任何失败都保留此前当前地图与已有存档，不能出现半条记录或先切换地图后才报错。

已有“导出我的实验”使用另一种包含样本和比较信息的格式。新的地图交换功能须使用任务书约定的单地图对象。名称和网格按契约往返保持；名称包含内部换行时也要检查实际下载文件，不能只看控件展示。

### 必试反例

- A05：非法 JSON、未知版本、顶层数组，核对错误信息及不变的状态。
- A06：分别导入缺 G、重复 S、不等宽的三个样例，不应出现任何半条存档。
- A07：依次导入 16,384 与 16,385 字节样例，解释字节数与字符数的区别。
- A12：下载实际导出文件，在空浏览器中导入，再刷新加载；同时核对文件恰好包含允许字段。

至少一次在操作前准备“当前地图 B + 已有存档 A”，用坏文件测试，证明失败没有改变两者。合法文件若存储写入失败，同样需要保持原状态。

提示 1：把文件大小、文件内容、结构校验与真正保存分成不同观察点。提示 2：画出哪一步失败时哪些旧值必须保留。提示 3：先测试一个只破坏一条规则的文件，再组合操作，不以错误消息出现代替状态检查。

自己解释：换浏览器后为什么需要手动导入？为什么服务器的 64 KiB 请求限制不能代替这次 16 KiB 文件限制？导出成功怎样才能证明文件真的能被另一个实例使用？

**阶段证据：**实际交换文件、接收方运行入口与反馈、文件大小、至少两个拒绝输入的前后状态、A12 往返结果。完成较快者增加 UTF-8、多字节名称或内部换行的反例，保持原契约。

## 阶段 5：同伴独立验收、恢复与交付

准备一份能由别人按说明启动的学生作品。让同伴从 A01–A12 中**独立选择至少三个反例**，其中包含无效文件、取消操作和存储失败；选择依据和操作由对方记录，自己先不要告诉对方预期实际输出。

再次运行原项目 37 项测试；针对自己的新增功能运行自己的测试或逐项人工验收。教师参考套件运行的是教师应用，不能把其结果写成你的作品已通过。记录每条命令或操作究竟指向哪个文件、提交或 diff、服务地址。

### 必须回归的原有行为

- A11：在同一张地图上求解、回放、手动移动与编辑仍可用。
- 分类预测之后仍需明确确认才移动；修改画板或相关数据后旧预测不能继续执行。
- 地图切换清除旧地图的对比；分类样本不混入地图存档。
- 完整复查 A01–A12，保留失败、未运行和环境阻塞项及下一步，不把它们改成通过。

提示 1：先确认每条证据指向哪个作品和版本。提示 2：请同伴只按记录重做一个反例，记下缺失信息。提示 3：对照同一输入在修改前后的结果，说明改动解决了什么以及还需要哪些回归。

### 做一次能够说明的代码恢复

先记录一个已验证版本，再在自己的练习副本做可逆的小修改并恢复。没有 Git 时，使用保留的文件副本恢复，记录它是“副本恢复”；它不能冒充 Git 提交回退。浏览器存档的数据恢复要另行处理，回退源码不会自动回退已经写入的地图。

要演练 Git 回退时，ZIP 使用者在**自己的练习副本根目录**执行 `git init`；完整仓库使用者先确认处于独立练习分支。逐个加入构成可运行版本的源文件，下面仅举两条路径，其他自写文件需自行补齐。未跟踪文件不能靠 Git 恢复；不要默认 `git add .`，不加入私人数据、依赖目录或密钥：

```bash
git status
git add projects/robot_playground/static/app.js
git add projects/robot_playground/static/index.html
git diff --cached
git commit -m "Record verified student work"
```

Git 缺少身份设置时请教师按本地练习规则协助。再做一次自己的小改动，审查并单独提交；确认工作区干净、`git log -1 --oneline` 正是这条练习提交，才运行：

```bash
git revert --no-edit HEAD
```

重跑对应测试和页面操作，记录恢复前、练习修改和恢复后的实际结果。不使用 `reset --hard`、强制推送或覆盖同学历史完成本题。

**阶段证据：**在自己的 `MY-SUBMISSION.md` 补齐作品入口、三个独立反例、失败—修复—回归、恢复记录、AI 使用情况和个人贡献。自己做 2 分钟解释，再完成教师指定的小修改或等价检查。

**自己解释：**你的哪条证据能被同伴重新得到？哪一项仍未验证？你修复的是功能、测试还是环境，依据是什么？

这些阶段是尚待真实课堂验证的教学设计。完成产品或测试通过，不能单独证明学习效果。
