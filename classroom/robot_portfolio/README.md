本目录把已有机器人项目组织成可发放的学生起点、先修诊断、渐进任务和提交证据。学生仍需实现 [CAPSTONE](../../curriculum/ai-assisted-development/CAPSTONE.md) 中的 V1/V2 存档与交换功能；首次课只完成起步，不要求 90 分钟做完整个项目。

## 课前：先验证实际发出的包

准备 Python 3.10+ 和普通浏览器。以下从完整仓库根目录执行；若本机使用 `python3` 或 Windows 的 `py -3`，统一替换命令中的 `python`。基础运行不要求 Node、Playwright、联网 AI 或 API Key。

```bash
python tools/robot_classroom.py doctor --port 8765
python tools/robot_classroom.py bundle --output dist/robot-student.zip
python -m zipfile -l dist/robot-student.zip
```

打包工具会创建缺失的输出父目录，但拒绝覆盖已有 ZIP。每次发放使用一个新文件名；解压也选择新的空目录。首次检查可用：

```bash
python -m zipfile -e dist/robot-student.zip dist/robot-student
cd dist/robot-student
python tools/robot_classroom.py doctor --port 8765
python -m unittest discover -s projects/robot_playground -p "test_*.py" -v
python -m projects.robot_playground.server --port 8765
```

核对原测试实际报告 **37 项通过**，再打开 **http://127.0.0.1:8765**，试一次 BFS、地图编辑和符号预测后的明确确认。结束服务用 Ctrl+C。若 8765 被其他进程使用，换一个空闲端口，并同时改启动命令和浏览器地址；已经启动的服务也会使该端口的再次诊断报告占用。

发放前还应查看包内根 `README.md`、`MANIFEST.json` 与 `fixtures/`：

- 包根直接包含 `projects/`、`tools/`、`classroom/` 等目录，没有额外套一层项目文件夹。
- 清单记录发包文件的字节数、SHA-256 和可取得的 Git 来源。`dirty` 为真表示发包时含未提交变化，不能把记录的提交号当成整个包的提交快照；无法取得来源时保留未知。学生开始修改后，不要求其文件仍与起始哈希相同。
- `fixtures/` 是后续验收输入，包含合法与损坏文件、名称和字节边界；它不会为原页面增加导入功能。原来的实验导出格式也不等于地图作品集格式。
- 白名单排除教师参考实现、故障解析、Git 历史及未列出的文件；教师本页和来源页也不进入学生包。发包隔离用于防止误发，公开 GitHub 仓库中的答案仍可被访问。

`doctor --port 8765 --json` 可保存结构化诊断。`ready` 只表示本次检查的基础运行条件满足；Node / Playwright 是可选提示，Chromium 的 `not_checked` 不是浏览器验收通过。诊断不安装软件、不联网、不修改配置；需要调整目录或启动方式时使用输出给出的命令。

学生包没有 Git 历史。安排版本回退活动时，让学生在自己的解压副本初始化练习仓库并保存基线，按[已有 Git 与回退工作卡](../../curriculum/ai-assisted-development/WORK-CARDS.md)操作。

## 首次两学时：90 分钟建议流程

采用 PRIMM 的预测—运行—调查—修改—创作顺序，并用短问题判断学生需要哪种帮助。[依据见 S2、S3](SOURCES.md)。两人一组，一人操作、一人复核；诊断阶段逐题换手，之后在 **65、77 分钟交换角色**。每人先写自己的预测和诊断结果，避免只保留小组共同答案。

| 时间 | 活动 | 当场留下的证据 |
|---|---|---|
| 0–20 分钟 | 按 START 解压、自检、运行原测试并打开页面。教师集中处理路径、解释器和端口问题 | 实际命令、URL、37 项基线结果或具体阻塞 |
| 20–40 分钟 | 独立完成 D1–D4；D4 可引用本次刚执行的基线记录。教师据诊断安排补练 | 每题独立／提示后／尚未完成状态及原始输出 |
| 40–47 分钟 · Predict | 阅读自己的计数脚本，为一张新 3×3 字符地图预测 `#` 和 `.` 的数量；另写出对页面刷新结果的预测 | 运行前的数值和理由 |
| 47–53 分钟 · Run | 运行脚本并在页面应用该地图；刷新验证预测 | 预期与实际的差异，保留一次错误预测也可以 |
| 53–65 分钟 · Investigate | 同伴互相解释循环与条件；追踪一次 `/api/solve` 请求，区分网格、JSON、页面临时状态 | 关键代码位置和简短数据流说明 |
| 65–77 分钟 · Modify | 在自己的诊断脚本中，将固定目标字符的计数改成可指定目标字符；保留旧输入，再加一个零匹配输入 | 一个小范围 diff、旧例与新例结果 |
| 77–87 分钟 · Make | 每人自建另一张合法地图，先预测再验证计数；为“刷新后继续修改”写一个用户故事和两条验收条件 | 自己的输入、预期结果，以及下次存档切片的目标 |
| 87–90 分钟 | 个人出口说明：一条已理解的数据流、一条待补知识、下一步验证动作 | 提交记录中的个人说明 |

诊断尚未完成的学生先沿原题补练；已完成者再扩展函数参数或边界输入。若启动耗时较长，可在同伴或教师机器上继续理解活动，把个人环境问题单独记录并随后复查；不要把设备问题当成概念错误。

### 无联网 AI 的等价安排

保留相同任务和验收标准。教师预先发放 ZIP、学习单与所需文档摘录；学生使用编辑器、浏览器开发者工具、本地测试和同伴讨论。把工作卡中的“向 AI 提问”改成向同伴或教师提交同一份需求、报错和最小复现。

使用 AI 的小组也先留下预测，并审阅实际 diff 和运行结果；未使用 AI 的学生在使用记录中写“未使用”即可。评价不取决于模型订阅、提问轮数或工具用量。

## 四项先修：教师核对与反馈

对应 [DIAGNOSTIC](student/DIAGNOSTIC.md)。这里是教师核对要点，不进入学生包；不新增诊断分数。反馈先指出一处具体误解，再让学生完成同类复查。

| 题目 | 教师核对要点 | 建议反馈与复查 |
|---|---|---|
| D1 · 读函数和循环 | 对 `['S#.', '..#', '..G']`，原条件统计 `#` 应得 **2**，改为 `.` 应得 **5**；学生应说明函数、两层循环、条件和返回值的作用 | 若把行数当计数，逐行列出匹配字符再相加；换一个零匹配输入，要求先预测再运行 |
| D2 · 页面、HTTP 与数据 | 点击 BFS 后可找到 `POST /api/solve`；能指出请求里的 `grid`、`algorithm` 与实际响应字段，并核对 `index.html → app.js → server.py → engine.py`。浏览器负责页面与请求，Python 服务处理求解；JSON 是交换数据格式 | 若只记住文件名，让学生指着 Network 中的一个请求解释“谁发送、谁处理、哪项数据返回”；再追踪一次其他算法请求，不能只复述答案 |
| D3 · 定位并恢复错误 | 在个人脚本末尾加入未定义的 `diagnostic_marker` 后，应记录实际文件、行号和 `NameError`；移除自己注入的那一行后重新运行。只恢复个人脚本，不改起始工程 | 若只截最后一行报错，让学生找到 traceback 指向的代码行，解释未定义名称；最小恢复后对照 D1 的已知结果 |
| D4 · 解读测试结果 | `37 tests ... OK` 表示这 37 项通过；`1 test ... FAILED` 是失败；`0 tests ... OK` 没有验证任何用例，不能算需求通过。学生还须有自己实际运行旧套件的数量和结果 | 若把退出成功当成验证完成，让学生同时指出用例数、失败数和被测范围；用实际命令重跑并解释“旧功能通过”仍缺什么新增功能证据 |

## 沿用原 100 分量规，按证据判断

下面仅把[已有评分维度](../../curriculum/ai-assisted-development/ASSESSMENT.md)对应到本单元，分值不变。形成性记录用于安排下一步学习，最终评分结合实际作品和个人说明。[过程评价依据见 S1、S3](SOURCES.md)。

| 原维度 | 原分值 | 本单元可观察的证据 |
|---|---:|---|
| 功能与用户体验 | 25 | 实际作品能保存、恢复、交换地图；取消操作、错误反馈、键盘和窄屏能完成主要任务 |
| 测试与失败处理 | 25 | 正常、边界和反例记录；至少一次可复现失败、修复与回归；有同学独立执行的反例 |
| 独立理解与现场修改 | 20 | 说明一次保存或导入的数据流；本人调整一条约束并更新验证；解释代码回退与数据恢复的区别 |
| 需求与取舍 | 10 | 用户故事、范围、数据契约、验收与已知限制一致，能解释一次取舍 |
| 安全与数据边界 | 10 | 地图仅保存约定字段，名称作为文本显示；确认规则及原有保护保留，不混入真实个人资料或密钥 |
| 工程交付与协作记录 | 10 | 他人按说明复现；有小范围 diff、版本记录、个人贡献及必要的脱敏 AI 使用记录，或明确写未使用 AI |

### 三类检查的对象不能混淆

| 检查 | 它能说明什么 |
|---|---|
| `doctor`、包清单、原 37 项测试 | 环境和学生起点是否可用，原测试断言是否满足；不验证学生尚未实现的存档功能 |
| [教师 A01–A12 套件](../../teacher_reference/robot_map_portfolio/ACCEPTANCE.md) | 它启动并测试教师参考实现，是备课目标和教师实现的回归检查；不是任意学生工程的通用评分器 |
| 学生作品的人工或自编测试 | 必须针对学生实际代码和实际 URL 执行，按 A01–A12 的行为要求逐项观察，并记录通过／失败／未运行／环境阻塞 |

教师或同学独立选择至少三个反例，记录被测版本、实际地址、输入、操作和结果。学生可以有不同界面与代码结构；不要仅因不匹配教师套件的选择器就判功能失败，也不要用教师服务的结果代替学生服务的结果。

需要故障定位活动时，直接复用已有[学生故障任务](../../teacher_reference/robot_map_portfolio/exercises/storage-write-failure/STUDENT.md)与[教师解析](../../teacher_reference/robot_map_portfolio/exercises/storage-write-failure/TEACHER.md)，按其说明建立独立练习副本；本学生起始包不附带这些答案。

## 试教记录

本课堂方案尚未试教。分别记录程序运行、学生独立完成情况、反馈后的修改和学习体验；自动测试全绿不等于学习效果。需要判断迁移时，在后续安排难度相近但题目不同的个人小改动，而不以成品截图或 AI 自评代替。
