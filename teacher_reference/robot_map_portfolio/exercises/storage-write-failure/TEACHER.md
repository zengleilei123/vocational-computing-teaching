# 教师解析：存储写入失败被当成成功

本页包含答案，应在学生完成独立复现与分析后再发放。目录只是组织材料，公开仓库不能保密。正常教师参考实现是正确版本；`fault.patch` 是一个默认不生效、需要在隔离副本中手动应用的单点故障。

## 教学目标与故障范围

本练习训练学生区分输入校验、浏览器持久化、页面状态和成功提示，形成可重复的“预期—实际—假设—验证—修复—回归”记录。它对应原 [ASSESSMENT.md](../../../../curriculum/ai-assisted-development/ASSESSMENT.md) 中的测试与失败处理、独立理解、工程交付等维度；不能仅凭测试全绿认定学生理解了机制。

补丁只修改 `teacher_reference/robot_map_portfolio/static/portfolio-core.js` 的 `persist(storage, records)`，不修改学生源码、测试断言、服务器安全边界或课程文件。具体变化是删除异常分支抛出的 `PortfolioError('storage-write', ...)`，换成注释，使控制流继续到正常返回值。

| 状态 | 写入是否完成 | `persist` 应有行为 | 故障版行为 |
|---|---|---|---|
| 正常写入 | 是 | 返回已保存记录的副本 | 相同，正常路径不暴露故障 |
| `setItem` 抛异常 | 否 | 抛出可读的 `storage-write` 错误，由页面保留状态并报错 | 异常被吞掉，返回看似成功的记录 |

存储写入抛异常时，测试替身和浏览器故障注入均不改变已有字符串。故障版仍把拟写入的记录交给调用方，页面因此可能显示成功及虚假列表；刷新后从真实存储重建，虚假新增或删除结果消失。改变输入校验、重试刷新或清空存储都没有修复这条错误传播路径。

## 独立验证运行器

从正常参考实现的仓库根目录运行，需要 Python 3.10+、Node 20+ 和 Git，无浏览器或第三方 Python 依赖：

```bash
python teacher_reference/robot_map_portfolio/tools/check_fault.py
```

需要保留完整 TAP 输出时：

```bash
python teacher_reference/robot_map_portfolio/tools/check_fault.py --verbose
```

脚本将 stdout/stderr 统一为 UTF-8，避免重定向保存中文报告时因系统默认编码而中断。若查看工具按其他编码打开日志，请选择 UTF-8。这里验证的是完整“基线—指定故障—恢复”三阶段，单独出现 `UnicodeEncodeError` 不是业务故障被正确发现的证据。[Python 标准流说明](https://docs.python.org/3.10/library/sys.html#sys.stdout)与[输出流重新配置 API](https://docs.python.org/3.10/library/io.html#io.TextIOWrapper.reconfigure)说明了相关编码条件与接口。

也可以将独立的真实 HTTP 浏览器 A09 纳入同一临时副本验证；这需要 README 规定的浏览器测试依赖：

```bash
python teacher_reference/robot_map_portfolio/tools/check_fault.py --browser
```

这个选项按基线、故障、反向补丁三个阶段调用 `python -m unittest teacher_reference.robot_map_portfolio.tests.test_acceptance -v -k A09`。基线与恢复后执行完整 A09 并必须通过；故障时额外使用 `--failfast`，要求恰好是 A09 内 `save` 子测试的断言失败。故障会改变页面显示，继续同一页面的后续子测试可能产生与准备状态有关的连锁错误，因此在已观测到目标失败后停止；那些未执行的子测试不能算通过。它继承 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 等现有浏览器设置，复制必要的原机器人模块作为只读依赖，不修改学生源码。缺少浏览器或其他错误不会被当成抓住故障。

运行器执行以下约束，任意一条不满足均非零退出：

1. 复制教师项目到系统临时目录，原参考实现和学生项目不接收补丁。比较教师项目、学生机器人项目和课程材料的文件哈希，确认运行前后不变；解释器缓存不计为源码。
2. 在副本运行整个核心套件，要求每一项通过，不能跳过、取消或只有文件级汇总。
3. 检查补丁只能改教师 `portfolio-core.js`，在副本应用补丁；再次执行相同测试集合，要求**仅**下面这条用例失败，其余通过：

   `A09 写入失败时保存、覆盖和删除均不伪报成功或改变已有存档`

4. 测试是真正调用保存、覆盖和删除，并观察异常、原始存储字符串与重新读取结果；不检查源码是否包含某个关键字来猜测故障。
5. 反向应用同一补丁，确认副本恢复原始文件字节，重新要求整个核心套件通过，最后移除临时目录。

故障未被抓住、错误测试失败、测试集合变化、意外修改测试或补丁失效都不能算练习材料通过。若未来重构代码或测试名称，须更新补丁与运行器，并重新取得完整三阶段运行证据。等价的学生修复不一定能再次应用这份精确文本补丁；学生修复以行为验收为准，不强求与参考答案逐字相同。

## 页面复现与预期结果

按 [STUDENT.md](STUDENT.md) 在隔离副本与 18766 端口复现，控制台只让本页、准确存储键的 `setItem` 抛出 `QuotaExceededError`。这样可以稳定制造失败，不依赖真的耗尽磁盘，也不要求改变浏览器安全设置。

在“操场 A”已经成功保存的基础上，拒绝写入后尝试保存“操场 B”：正确版本显示失败，列表与原始字符串都维持 A；故障版本会返回拟保存的 A/B 列表并触发错误的成功反馈，原始字符串仍只有 A，刷新后 B 不存在。确认覆盖和确认删除使用相同的持久化边界，也应逐一观察。测试注入可以通过控制台恢复函数或刷新撤销；它不是生产代码的一部分。

浏览器回归命令：

```bash
python -m unittest teacher_reference.robot_map_portfolio.tests.test_acceptance -v -k A09
python -m unittest teacher_reference.robot_map_portfolio.tests.test_acceptance -v
```

两条命令必须走真实本机 HTTP。缺失依赖或浏览器访问被环境阻塞，应保留原始错误并标记未完成，不把跳过算作通过。

## 精确修复

将故障版异常分支恢复为抛出领域错误，使调用方进入失败处理，避免更新列表或报成功：

```diff
     } catch (_error) {
-      // Continue so the caller can display the in-memory records.
+      throw new PortfolioError('storage-write', '本地存储写入失败，存档未更新。请检查存储权限或剩余空间，并导出地图备份。');
     }
```

若只需要将**已应用原故障补丁、尚未作其他修复的隔离副本**恢复到参考版本，可以反向应用：

```bash
git apply --check --reverse teacher_reference/robot_map_portfolio/exercises/storage-write-failure/fault.patch
git apply --reverse teacher_reference/robot_map_portfolio/exercises/storage-write-failure/fault.patch
node --test-reporter=tap teacher_reference/robot_map_portfolio/tests/core.test.cjs
```

已经修复或有其他编辑时，不要强制套用反向补丁；先检查 diff，保留学生分析与改动，再选择最小恢复步骤。反向补丁命令不替代学生对根因的解释。

## 评分检查点

下列检查点用于原课程量规，不另改总分或给模型使用量加分。

| 检查点 | 达标证据 | 尚未达标的表现 |
|---|---|---|
| 可重复复现 | 先有绿色基线；故障后指定 A09 失败；记录浏览器来源、输入、操作与原始字符串 | 只展示一个红色报错或截图，不能重复 |
| 根因与数据流 | 说清 `setItem` 失败、返回值、页面成功处理及刷新重新读取之间的因果 | 仅说“加一个 try/catch”或归因于 AI / 浏览器 |
| 小范围修复 | 修改失败传播边界，保持正常写入与其他存档操作；不修改测试或学生起点 | 清空存档、删除失败断言、将异常都视为成功 |
| 真实验证 | 核心套件、A09 与完整浏览器回归；未运行项如实标注 | 把跳过、离线 DOM 或旧截图写成真实 HTTP 验收 |
| 个人理解与迁移 | 独立解释为什么覆盖、删除和导入也受影响，能现场调整一条相邻边界并验证 | 只能背诵修复语句，不能解释后果 |
| 工程记录 | 失败—修复—回归证据、最小 diff、已知限制、脱敏 AI 使用记录 | 只交完整聊天或最终成品 |

可用 5–10 分钟现场问答检验：哪个返回值让页面判断成功？若 `getItem` 而不是 `setItem` 失败，应该观察什么？为什么先保存成功再回退代码，地图仍可能存在？允许查看官方文档，现场解释由学生本人完成。

## 代码回退与数据回退是两件事

Git 工作树、反向补丁或源码回退只改变文件。浏览器的 `localStorage` 位于浏览器配置中，按包含端口的来源隔离，不随 Git 提交回退；已经成功写入的地图不会因代码恢复而消失。反过来，删掉存储键也没有修复程序。

需要恢复数据时，先在出问题来源的开发者工具中备份 `robot-map-portfolio:v1` 的完整原始字符串，再决定修复副本或有意删除这一项并重新导入。不要使用 `localStorage.clear()`。整个容器无法解析或不是数组时，应用保留原字节并阻止修改；数组中部分记录损坏时，读取显示有效项及警告，但后续成功修改会写回恢复后的有效集合，故应在那之前备份。

练习结束可停止 18766 服务、保留作业记录并移除独立工作树或复制目录。删除目录不会删除对应来源的浏览器存档；如需清理测试存档，应在正确来源上单独、明确地操作。不要把清理练习目录或删数据算作功能修复。
