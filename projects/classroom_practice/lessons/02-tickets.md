# 项目二：校园报修工单分类（学生任务书）

## 业务委托

运维人员收到“网络断开”“键盘坏了”“软件安装失败”等描述，希望系统给出处理类别建议；不确定的情况交回人工，不直接自动派单。
目标是亲手经历 **业务标签 → 数据 → 特征 → 训练 → 预测 → 评价 → 错误分析**，而不是调用一个API即结束。
先修：Python字典/Counter、CSV、基本概率与对数；建议8学时。贝叶斯公式可先用计数表解释，再推导。

## 数据与标签

[data/tickets.csv](../data/tickets.csv)包含57条原创合成描述，字段为id、group、split、text、label。
标签为 network（网络）、hardware（物理硬件）、software（应用/环境）。组合故障、缺少信息、域外问题不适合强行单标签，真实版本应加人工复核流程。
训练36条、验证9条、测试12条，均衡分布只是教学安排，不反映真实业务。

`group`用于将同一表达家族的改写放在同一数据子集。程序检查同组不能跨集、同一规范化文本不能跨集；语义近重复仍须人工检查，不能认为填了group就完全无泄漏。

## 四次课，每次2学时

### 第一次：标注规范与规则基线
学生各自标注6条描述，交换结果讨论分歧。写关键词规则并记录它在哪些句子上会失效。不追求一开始就写模型。
交付：标签定义、争议记录、数据划分说明、规则结果。

### 第二次：从数据学习参数
用相邻两个字符构成特征，例如“网络断线”→“网络”“络断”“断线”。只用训练集建立词表，统计每类样本数和每类特征出现次数。
固定Laplace平滑alpha=1：P(term|class)=(该类term计数+1)/(该类全部特征计数+词表大小)。预测时把各特征对数似然与类别先验相加。
这是简化的多项式朴素贝叶斯；字符特征不真正独立，假设与局限也需要讲。代码不依赖scikit-learn，但可后续与其实现对照。
交付：手算一个两类小例子，解释`fit`学到了什么，比较手算与代码。

### 第三次：评价不是只看准确率
分别打印验证集和测试集的类别顺序固定的混淆矩阵、accuracy、macro-F1、转人工比例与逐条失败样本。
训练词表不能读取验证/测试文本；修改测试标签不能影响拟合结果。验证集用于后续选择参数；测试集只用于最终报告，不能反复针对测试错题调参再称作独立泛化。
本参考实现alpha与margin预先固定，没有利用测试集调参。margin为第一、第二类对数得分差，不是校准后的置信度；低margin或全未知特征转人工。

### 第四次：错误复盘与需求变更
保留真实运行错例：“网络正常但应用升级后打不开”。讨论为何字符共现可能忽视否定与上下文。不要把这句话硬编码为正确答案来抬高测试分数。
新增一批独立来源的脱敏/合成训练表达，版本化保存后重新评价；若实际收集校园数据，必须先获得许可并删除身份信息。课堂可以只使用新合成文本。

## 分层任务

基础：读取数据、计数特征、打印规则分类结果。
提高：训练并解释朴素贝叶斯，输出混淆矩阵和macro-F1。
挑战：仅在验证集选择转人工阈值；比较word/character特征；给出误派成本与人工量之间的权衡。TF-IDF/逻辑回归/LLM对照属于扩展，当前参考解未实现。

## 核心验收与评分

数据/划分20；模型实现25；指标与回归25；错误分析20；可复现和个人解释10。
**不按测试集分数高低直接给学生分数**：泄漏造成的高分可能比正确报告低分更差。
交付：数据卡、训练代码、参数记录、报告JSON、至少3个失败或边界分析（可包含人为构造但须标注）、来源/许可说明。
