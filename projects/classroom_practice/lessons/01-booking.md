# 项目一：实训室设备预约（学生任务书）

## 业务委托

实训管理员希望学生预约摄像头或机器人套件。同一设备同一时段只能被一个人预约；学生可以取消自己的预约；误点两次不能产生两条记录。

本课模拟一个校内服务，不接真实设备、不收集真实学号。先修：Python函数、异常、SQL增查改。建议6学时。

## 业务规则与输入输出

设备：`camera-01`、`robot-01`。用户：合成ID，例如`demo`、`other`。
输入为 request_id、student、equipment、start、end。时间为带时区的ISO8601，例如`2026-11-02T09:00:00+08:00`，内部统一成UTC整秒。
单次预约大于0且不超过8小时。时间区间为 **[start,end)**，09:00—10:00和10:00—11:00可相邻。

| 场景 | 应有结果 |
|---|---|
| 首次预约空闲设备 | 保存confirmed记录 |
| 重叠预约同一设备 | 拒绝，数据库不能残留第二条记录 |
| 相同request_id、完全相同参数重试 | 返回已有记录，不重复写入 |
| 同request_id更换人或时间 | 拒绝，不把旧预约悄悄改掉 |
| 学生取消其他人的预约 | 拒绝 |
| 自己显式确认取消 | 状态变cancelled，时段可再次预约 |
| 取消后重复提交旧request_id | 返回cancelled，不恢复预约 |

## 分阶段任务

### 第1—2学时：先不用数据库
用列表存预约记录，独立写出重叠判断。画出完全包含、局部重叠、完全相等、端点相接四种情况。证明判断条件是 `existing.start < requested.end and existing.end > requested.start`。不要直接把两个开始时间比较大小当作冲突判断。

### 第3—4学时：加入SQL
设计设备表、预约表、主键和外键。将列表版替换为参数化SQL；解释为何没有手工拼接用户字符串。补上重复请求、未知设备和非法时间测试。

### 第5—6学时：并发与事务
让两个独立数据库连接同时预约一台设备。解释“先查再插”为什么必须放在同一写事务中；使用BEGIN IMMEDIATE串行化写入尝试。第二个连接等待第一个提交后，应发现冲突，而不是也成功。
SQLite忙错误、超时和重试策略属于进一步讨论，不能把单次并发测试当作生产压力测试。

## 分层要求

基础：输入校验、预约、查询和取消。
提高：幂等请求、时区归一化、数据库持久化。
挑战：双连接冲突测试；解释数据库锁、业务冲突和身份授权是三个不同概念。追加需求“设备维修时不可预约”时，先增加失败测试，再改实现。

## 教师故障注入练习

在学生自己的副本中，临时把区间比较改为`<=`，观察相邻时段测试失败；临时移除事务，讨论为什么并发问题可能偶发、单线程测试可能发现不了；不得把故障版提交为参考主分支。

## 提交与评分（建议100分）

提交：两张表的数据字典、流程说明、代码、至少6个测试、一次并发演示结果、个人答辩记录。
正确性40；测试与失败分析25；数据设计与文档15；安全边界10；个人现场解释10。
UI不是必做项；只做漂亮页面但允许重复预约，不算通过核心验收。

现场提问：为什么相邻时段不冲突？重试为何不能直接生成新ID？谁提供可信的student身份？为什么传`confirmed=True`不等于已经验证用户身份？
