# 校园机器人挑战场：先玩出问题，再写出答案

一个本机、离线、可编辑的双项目教学工坊。学生不仅运行教师代码，还可以自创地图、编写策略、采集自己的像素符号、让同学测试并展示失败改进。不是 RAG 包装，不需要 GPU、API Key、摄像头或外部服务。

## 启动

从仓库根目录，用 Python 3.10+：

```bash
python -m projects.robot_playground.server --port 8765
```

浏览器打开 **http://127.0.0.1:8765**。必须通过这个本地服务运行，不要直接双击 HTML。Ctrl+C 退出。程序只监听本机；不能用于公网部署，也没有实现真实机器人控制或多人在线服务。

## 玩法一：我比机器人更会找路

先用方向按钮或方向键走到 G，再试 BFS、Dijkstra 和“我的直走策略”。路线可逐步播放，展示步数与模拟能耗；没有路时明确返回失败，而不是给一个虚假的完成分。

- **挑战 1：近路不一定省电。** 固定地图中 BFS 为 6 步 / 能耗 46，Dijkstra 为 10 步 / 能耗 10。数值来自进入格子的模拟成本，不是实测电池能耗。
- **挑战 2：绕路才能到达。** 默认 `student_strategy.py` 只先横后竖，会撞墙。学生改这个文件，保持 `plan(grid) -> list[str]` 契约，使用同一个评分器验证。
- **挑战 3：不可能任务。** 明确报告无路；学生可以修改地图让它可解，并解释最小修改。
- **创作任务：** 用画笔添加墙和高耗能区，移动起终点；也可复制字符地图给同学。地图改变即清空原对比，不能拿不同地图的数值做排名。

数据用矩阵表示：`S` 起点、`G` 终点、`#` 墙、`.` 普通地面、`2–9` 进入成本。最多 20×20，最多 400 个动作；只允许上下左右。起点不扣能耗，进入终点扣 1。只允许一个起点和一个终点。

## 玩法二：我教机器人认识我的暗号

在 5×5 画板上画符号，并标为上/右/下/左。符号不必是标准箭头，由学生自主选择。四类至少各一个训练样本后，可以识别新图；**预测不会立即移动，必须再点击确认**。

- 训练采用 **k-NN**：保存标注样本，用二值像素距离寻找最近邻；没有神经网络训练或 LLM 推理。
- `k=1/3/5`；邻居投票占比不是校准概率。默认合成样本仅 4 个，适合 k=1；k>1 需要增加每类独立样本。
- 空白、距离过大或规定的平局会拒识；固定距离阈值 0.32 是教学设定，未经真实数据标定。
- “加入训练集”和“留作测试”分开；测试图像不会参与预测。同一图像在训练/测试集合重合时保守拒绝评测；这只防止完全重复，不保证没有近重复或其他泄漏。
- “载入合成示例”明确替换当前数据，便于先体验；正式作业使用自己的样本。刷新页面会清空临时状态，可主动导出 JSON 保存。
- 留出集结果展示准确率、可判断比例和逐条错例。不要反复看同一测试集调参再把它当独立测试；调整后另收最终盲测集。

## 教什么、改哪里

| 学习内容 | 代码位置 | 学生交付 |
|---|---|---|
| 二维数组、循环、状态与函数 | `engine.py` / `static/app.js` | 解释一次移动，制作自定义关卡 |
| 队列、BFS、堆与 Dijkstra | `engine.py` / `student_strategy.py` | 改进策略，比较同一地图下的代价 |
| 标注、距离、k-NN、拒识与数据划分 | `glyphs.py` | 自己的样本、独立测试和失败分析 |
| HTTP、JSON、前后端分离、边界校验 | `server.py` / `static/` | 追踪一次请求与响应，增加边界测试 |
| 测试、复现和证据 | `test_playground.py` | 一个可重现失败、修复及回归测试 |

## 测试

```bash
python -m unittest discover -s projects/robot_playground -p "test_*.py" -v
node --check projects/robot_playground/static/app.js
```

Python 测试包含真实本机 HTTP。可选浏览器测试需要额外开发依赖 `playwright` 和 Chromium：

```bash
python -m pip install playwright
python -m playwright install chromium
python -m projects.robot_playground.tools.browser_smoke
```

测试工具支持 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定已安装浏览器。受限环境可设 `ROBOT_OFFLINE_DOM=1`：此时用真实业务函数驱动离线 DOM 交互，不做浏览器 HTTP 导航；HTTP 仍由单独的接口测试验证，不能冒充完整端到端测试。

## 已验证与未验证

本轮本地 Python 3.13.5：37 个自动测试通过；Chromium 离线 DOM 检查覆盖 14 类操作，1440×1100 与 390×844 页面无脚本异常、无横向溢出。受运行环境浏览器网络策略限制，浏览器连接本机服务的完整端到端模式未在本环境跑通；没有修改浏览器安全策略。项目原有课程测试是否通过以相应提交的 GitHub Actions 为准。

无真实课堂有效性证据。浏览器样本只在内存，服务不保存、不外发；导出是用户主动保存的文件。没有公开排行榜、账号系统、真实个人信息或自动成绩写入。

## 与已有课程衔接

机器人项目负责激发问题与积累算法/编程/评测证据，不替代 SQL、事务或正式课程。`导出我的实验` 是未评分证据；教师人工验收后，可按已有 `projects/classroom_practice/data/assessments.csv` 的 `evidence_id,student,project,topic,score` 格式登记，再用原有验收流程接入 CoursePilot。此处**未实现自动导入**，不把游戏能耗或分类准确率当学生成绩。
