# 从一条需求讲清整套系统

## 课前准备
学习者会 Python 函数、列表/字典与命令行。项目数据是合成数据，无需 GPU、账号或密钥；先运行离线 demo 和 tests。示例课按 90 分钟设计，是教师建议稿，不是已完成的课堂实验。

## 90 分钟示范课

| 时间 | 教师演示 | 学生要产出的证据 |
|---|---|---|
| 0–10 | 提出“我学过 Python，想学智能体” | 写出输入、输出，以及哪些事实不能靠模型猜 |
| 10–25 | 查看 SQLite 的 attempts，用 GROUP BY 得到平均分 | 手算一个知识点，再与查询结果核对 |
| 25–40 | 将 agents 的先修图展开并拓扑排序 | 自己排列顺序；构造一个环，说明报错原因 |
| 40–50 | 检索“工具调用参数校验”，展示原文来源 | 改成无关问题，确认不编造资料 |
| 50–65 | 对比 offline_run 和 run_llm 的调用链 | 标记哪些步骤是代码决定，哪些可由模型决定 |
| 65–75 | 展示 pending→approved 及未确认失败 | 证明模型工具列表没有 approve，字符串 true 不通过 |
| 75–85 | 调用 HTTP API 并运行测试 | 截取 401、合法响应和至少一条失败测试 |
| 85–90 | 总结分层与局限 | 解释“8/8 回归通过为什么不等于模型 100% 准确” |

## 分层练习（同一项目）

**基础**：为 SQL 增加第二条合成记录，算出更新后的平均分；为检索新增一个术语；追踪一次请求调用的函数。

**提高**：给课程图增加一个有两个先修的课程；实现输出课程中文标题；写出图循环、未知课程、无检索证据、无确认四类负例。

**挑战**：在不改变服务接口的情况下替换检索器；为同一组问题比较关键词与向量方法。先制定评价数据再改模型，不能反复调整测试集以美化结果。

## 一条需求的分工表

“读取真实状态”交给数据库；“满足先修顺序”交给图算法；“提供资料依据”交给检索；“理解语言并选择工具”可以交给模型；“决定允许执行什么”永远留给应用；“证明是否更好”依靠测试与独立评价。

## 评分建议（100 分）

业务贯通 25；数据与算法正确性 25；错误与权限边界 20；测试证据 20；解释与复现 10。只展示漂亮聊天界面、不能解释 SQL/算法/失败处理，不算完成。

## 教师能力积累

每个教学单元保留教案、学生起始版本、分层任务、参考实现、测试、评分依据和试讲记录。当前仓库实现属于参考答案；不要直接当成必须由零基础学生一次写出的作业。学生使用 AI 时记录用途，并用现场改需求、解释错误和补测试验证独立能力。
