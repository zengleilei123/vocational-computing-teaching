# 一个项目贯穿计算机与人工智能课程

## 不是堆技术名称，而是为同一个业务问题逐层补能力

主项目：[CoursePilot 智能课程助教](../projects/coursepilot/README.md)。角色、课程主题、学习记录、计划对象从头到尾保持一致。

学习目标：让学生解释“为什么需要这项技术、输入输出是什么、失败时怎么办”，而不只是安装框架。保留 `curriculum/` 的小实训作为知识点练习，`projects/coursepilot/` 负责综合应用。现有 RAG 课程是其中一站，不是项目终点。

## 能力链与代码对应

| 阶段 | 同一个项目增加的能力 | 必讲知识 | 当前落点 | 学生验收 |
|---|---|---|---|---|
| 1 程序设计 | 表达课程、练习、学习者 | 变量、集合、字典、函数、异常 | core.py 的 TOPICS/NOTES | 不看答案解释输入到输出 |
| 2 数据工程 | 导入合成练习记录 | CSV、字段校验、缺失值、有限数、批次原子性 | Store.import_csv | 一条坏记录不能导致半批数据入库 |
| 3 数据库 | 数据持久化与统计 | 主键、外键、参数化 SQL、GROUP BY、事务 | Store.progress/plan | 解释平均分如何计算及局限 |
| 4 数据结构算法 | 产生有先后顺序的学习路径 | 有向图、依赖闭包、拓扑排序、环检测、O(V+E) | learning_path | 给出环反例；验证每个先修约束 |
| 5 软件工程 | 多个入口调用同一服务 | 模块分层、接口契约、测试替身、错误传播 | core/agents/api/app | CLI 和 API 的同一输入得到相同业务结果 |
| 6 信息检索 | 为建议提供可追溯证据 | 关键词基线、排序、来源、拒答、误命中 | Store.search | 有关问题命中、无关问题不伪造依据 |
| 7 智能体 | 模型决定何时调用工具 | Schema、消息往返、白名单、调用预算 | run_llm；可选真实接口 | 模型不能通过参数切换身份或批准计划 |
| 8 工作流与安全 | 计划先草稿再确认 | 状态机、显式确认、幂等、审计 | pending→approved | 字符串 "true" 不能冒充布尔确认 |
| 9 后端与网络 | 对外提供本地接口 | HTTP、JSON、401/400/404、请求体限制 | api.py | 实际 HTTP 验证未授权/合法/非法请求 |
| 10 测试与评测 | 可重复比较版本 | 单元/集成/端到端、正负例、指标分母 | tests + evaluate | 每个报告写清是否调用真实模型 |
| 11 运行与交付 | 别人可以复现 | 环境变量、命令行、Linux 进程、Docker、CI | app.py / Dockerfile / Actions | Python 测试、真实 API、容器各自报告 |
| 12 前端（后续） | 学生查看证据、老师确认计划 | HTML/CSS/JS、fetch、表单、访问性、认证 | 复用现有 API，不另建业务规则 | 前端不能绕过后端确认和身份约束 |

这是跨课程的项目映射，不主张在一门 32 学时智能体课里从零教完全部计算机基础。基础课先完成 1–4，软件工程与实训承担 5、8–11，AI 课深化 6–7；学时由实际学情决定。

## 人工智能教师方向：再往下讲到模型，而不是停在 API

下面都是**后续阶段设计，未宣称已实现**。仍使用相同业务和数据模型，每阶段只增加一类复杂性。

| 增量 | 为什么此时需要 | 应交付的实验 | 必须区分的指标 |
|---|---|---|---|
| 传统机器学习 | 规则判断“查资料/看学情/制订计划”可能漏掉表达 | 同一意图任务对比关键词规则、TF-IDF+线性分类器与 LLM | 按学生/模板隔离训练与测试；macro-F1、混淆矩阵、延迟 |
| 推荐与学习分析 | 70 分阈值不一定反映知识掌握 | 规则、统计模型和学习者反馈对照 | 离线排名指标不等于学生学习收益 |
| 向量检索与重排 | 关键词遗漏同义表达 | 固定语料和测试集比较关键词、Embedding、混合检索、Rerank | Recall@k/MRR 与答案引用正确率分开 |
| RAG 生成 | 找到片段仍需组织可读回答 | 相同检索证据下比较模板、模型回答、拒答策略 | 事实支持率、引用有效性、拒答的精确率/召回率 |
| 工具调用对齐 | 模型错选工具或填错字段 | 固定测试集比较提示词与小规模微调；先查数据质量 | 工具选择、参数正确性、任务完成、越权率分开 |
| MCP | 工具需被多个客户端复用 | 将现有 progress/search 工具封装为服务 | 协议正确性不等于权限安全 |
| 语音/视觉 | 学生口述问题或提交屏幕截图 | ASR/Vision 接入同一任务接口；保留文本基线 | 感知错误与决策错误分开；增加延迟与隐私约束 |
| 多智能体 | 单控制器确有复杂任务瓶颈 | 只在备课/出题/审阅有独立职责时与单体比较 | 成功率与成本/时延一起报告 |
| 生产化 | 需要多用户、真实权限和长期使用 | FastAPI/生产服务器、真正身份体系、持久化与备份 | 不用本地 HTTP 演示冒充生产部署 |

不为了“覆盖所有技术”强塞 Kubernetes、训练大模型、复杂向量数据库或多智能体。数据库和图算法可以精确解决的子问题，不交给语言模型猜。

## 如何把刷题变成项目教学

- 字典计数：按 topic 统计练习记录，随后与 SQL GROUP BY 对照。
- 排序与 Top-k：对检索候选排序，解释固定 k 与阈值的区别。
- 图遍历：求目标课程所有祖先；构造环后说明为什么不能产生合法顺序。
- 队列：按先修依赖释放学习任务，再讨论异步工作队列为何是另一个问题。
- 动态规划（后续）：有限学习时间下的课程取舍；说明它不能替代先修约束验证。

每道题保留输入、输出、正确性解释、复杂度、边界和变式；不要复制第三方题库后标作原创。

## 建议的分阶段交付

1. **目前版本**：完成数据→算法→检索→工具→确认→评测的纵向贯通，先讲清原理。
2. **下一阶段**：前端工作台与课程单元，把每个按钮对应到现有 API、服务、SQL 和测试。
3. **再下一阶段**：意图分类训练及检索对照实验，把“模型如何训练和评价”接到应用上。
4. **深化阶段**：真实模型评测、MCP、语音视觉，始终维护无模型基线与固定回归集。

## 研究与设计依据（2026-10-28 核对）

- [Anthropic: Building effective agents](https://www.anthropic.com/research/building-effective-agents)：区分确定性工作流与模型控制的 agent；优先简单可组合模式。本项目据此保留两个入口，不将固定流程叫自主推理。
- [OpenAI: Function calling](https://developers.openai.com/api/docs/guides/function-calling)：模型提出调用、宿主执行并回传结果。本项目保留名称/参数/调用预算校验；具体服务商兼容性单独测试。
- [Python sqlite3](https://docs.python.org/3.11/library/sqlite3.html)：参数绑定、事务和轻量本地数据库。本项目采用占位符，不拼接用户 SQL。
- [Python graphlib](https://docs.python.org/3.11/library/graphlib.html)：拓扑排序及循环检测。图来自教师定义，不来自模型猜测。
- [Python http.server](https://docs.python.org/3.11/library/http.server.html)：文档明确不建议用于生产；这里仅演示本机 HTTP 请求链路。
- [教育部计算机类专业教学标准入口](https://www.moe.gov.cn/s78/A07/zcs_ztzl/2017_zt06/17zt06_bznr/bznr_zyjyzyjxbz/gdzyjy_zk/zk_dzyxxdl/dzxxdl_jsjl/)：用于定位课程培养范围。本项目不是官方标准或学校已批准的人才培养方案。

引用仅说明设计来源，不能推出本项目已在真实课堂验证有效。
