# 机器人地图课程：课堂发放与首次学习设计

## 目的与依据

用户要求继续优化已合入 main 的教学仓库。本轮把“有材料”推进到“能够发放、启动、按阶段学习并提交证据”，服务高职初学者和备课教师。当前基线为 `12524f73ef75ee0f5df57eb0e1aa97f2802e2633`。

现有教师 V1/V2、A01–A12 和故障补丁继续复用。审计发现学生起点缺少可复现发放包、启动环境诊断、可执行先修诊断和课程专用提交模板；教师参考测试固定启动教师服务，必须标明验收对象。

## 方案选择

维护者在本轮自主选择 Python 标准库工具加 Markdown 学习单：复用现有技术栈，离线运行，也适用于普通 ZIP 分发。另建教学平台会增加账号和部署成本；继续只增加概念性文档无法验证实际发出的材料能运行。本轮不建立新平台。

## 具体交付

1. `tools/robot_classroom.py` 提供 `doctor --port 8765 [--json]` 和 `bundle --output PATH.zip`。诊断 Python 3.10+、运行所需文件、当前目录及回环端口；Node/Playwright 仅为可选开发检查，不阻止基础运行，不安装、不联网、不修改配置。
2. 发包采用显式文件白名单，保留原机器人源码、测试与必要教学文档、CAPSTONE/WORK-CARDS/SOURCES、学生学习单、工具及许可证。排除教师参考实现、故障答案、Git 历史和任意未列出文件。包内生成入口 README、输入样例和含 SHA-256 的清单。记录工作树的 Git 来源及是否有未提交变化；不把工作树内容冒充提交快照。缺文件、源文件或源目录为符号链接、输出目标已存在（包括断链）时明确失败，不覆盖既有文件。用户选择的输出父目录按正常文件系统路径解析，不承诺拒绝系统目录链接。
3. 包内输入样例覆盖合法地图、非法 JSON、未知版本、缺终点、重复起点、不等宽、HTML 名称、40 码点名称、16384/16385 字节边界；只是验收输入，不实现学生功能。相同内容和来源信息产生相同 ZIP。
4. `classroom/robot_portfolio/student/` 提供首次启动、四项先修诊断、五个渐进里程碑、可复制的提交与 A01–A12 证据表。提示不直接给保存/恢复的参考代码。无联网 AI 时仍完成相同学习任务。
5. 教师入口给课前检查、建议的首次两学时流程、诊断反馈和既有评分维度的证据映射。方法参考教育部软件技术专业教学标准与 Raspberry Pi Foundation 的 PRIMM；明确这是课程设计，尚无本课程教学效果数据。
6. CI 在 Ubuntu/Python 3.11 和 Windows/Python 3.10 验证工具、实际学生 ZIP 与原机器人测试；既有完整浏览器套件保留。教师验收文档显著说明其目标，不能自动给学生作品评分。

## 不变量与边界

- 不修改 `projects/robot_playground/` 的任何文件及 `CAPSTONE.md`；地图存档仍由学生实现。
- 不引入产品服务、API Key、学生真实身份、自动成绩或付费要求。
- 公开仓库的分发隔离不是保密措施；文件清单只防误发，不阻止访问公开源码。
- 环境检查不等于功能验收；旧测试和教师参考测试通过不等于学生新增功能通过。
- 端口检查只反映检查瞬间；缺 Python 时学生须先按启动说明安装解释器。
- 学生包不带 Git 历史，Git 回退练习需自行初始化自己的练习仓库。
- CLI 的文本与 JSON 使用 UTF-8 输出，重定向不依赖操作系统的默认文字编码。
- 可捕获的写入异常和用户中断应清理本次未写完的 ZIP；这不是断电或强制杀进程下的持久化保证。
- 学生提交模板复制到同目录 `MY-SUBMISSION.md`，保留相对链接并兼容 Windows 文件名规则。

## 完成标准

解压出的包能在自己的根目录启动学生服务、运行原 37 项测试；无法导入教师参考模块；源码与基线学生项目逐字节一致。缺文件、符号链接、错误端口和已有输出均有明确失败证据。学习单链接、命令和验收对象正确。完整工作经过独立审查及对应 CI 后交付主分支。
